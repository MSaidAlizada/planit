# planit

Self-hosted task and calendar manager. Automatically schedules tasks into free
time based on deadlines, duration, mental load, and sleep preferences.

## Architecture

- **Frontend** — React + Vite + TypeScript, deployed to GitHub Pages.
- **Backend** — FastAPI + SQLModel + SQLite, running in Docker on a Raspberry
  Pi, exposed publicly over [Tailscale Funnel](https://tailscale.com/kb/1223/funnel)
  (stable HTTPS hostname, no port forwarding or router config needed).

Frontend and backend run on different origins, so auth uses Bearer tokens
rather than cookies — cross-site cookies get inconsistently blocked by
browsers' third-party cookie policies. See [Auth](#auth) below.

## Stack

| Layer | Choice |
|---|---|
| Frontend | React + Vite + TypeScript, custom CSS |
| Backend | FastAPI + SQLModel + SQLite |
| Auth | Short-lived JWT access tokens + rotating refresh tokens, invite-gated registration |
| Background jobs | APScheduler (in-process) |
| Migrations | Alembic (`migrations/` dir, `render_as_batch=True` for SQLite) |
| Deployment | Docker Compose (backend, on the Pi) + GitHub Actions (frontend, to Pages) + Tailscale Funnel (public ingress) |

## Running locally

```bash
# Backend
cd backend
../.venv/bin/python -m uvicorn app.main:app --reload --port 8000

# Frontend
cd frontend
npm run dev -- --host 0.0.0.0 --port 3000
```

The dev server proxies `/api` to `localhost:8000` (see `vite.config.ts`), so
frontend and backend are same-origin in development — no `VITE_API_BASE_URL`
needed locally.

## Auth

- The **first person to register becomes admin** automatically, no invite
  code needed.
- Every registration after that requires a valid invite code, generated by
  an admin:

  ```bash
  curl -X POST https://your-backend-url/api/auth/invites \
    -H "Authorization: Bearer <admin access token>" \
    -H "Content-Type: application/json" \
    -d '{"max_uses": 1, "expires_in_days": 7}'
  ```

  List active codes with `GET /api/auth/invites`, revoke one with
  `DELETE /api/auth/invites/{code}` (admin-only).
- Sessions: 15-minute access tokens (Bearer, kept in memory on the frontend)
  plus 30-day rotating refresh tokens (localStorage). Refresh tokens rotate
  on every use; presenting an already-rotated token is treated as theft and
  revokes the whole session.
- Login is rate-limited per IP and locks an account for 15 minutes after 5
  consecutive failed attempts.

## Admin CLI

Manage users directly on the backend, without going through the API:

```bash
docker compose exec backend python manage_users.py list
docker compose exec backend python manage_users.py delete <username>
docker compose exec backend python manage_users.py delete <username> --yes  # skip confirmation
```

Deleting a user removes *all* of their data — tasks, habits, calendar
events, categories, contexts, preferences, feeds, Google credentials, and
any invite codes they issued — not just the account row.

## Deploying

### Backend — Raspberry Pi, Docker, Tailscale Funnel

```bash
docker compose up -d --build
```

On a Pi 3B (1GB RAM) this build is slow and memory-constrained — expect
several minutes, mostly spent on `pip install` and the image export step.
It won't crash, just be patient rather than interrupting it.

Set secrets in `backend/.env` (see `backend/.env.example` for the full list):

```
JWT_SECRET_KEY=<long-random-string>
CORS_ORIGINS=["https://your-username.github.io"]
GOOGLE_CLIENT_ID=<from Google Cloud Console>
GOOGLE_CLIENT_SECRET=<from Google Cloud Console>
GOOGLE_REDIRECT_URI=https://your-backend-public-url/auth/google/callback
FRONTEND_URL=https://your-username.github.io/planit
```

Expose the backend publicly (no port forwarding, no router changes):

```bash
sudo tailscale up --ssh          # once, to join your tailnet
sudo tailscale funnel --bg --https=443 8000
```

Funnel needs one-time approval in the Tailscale admin console the first
time you enable it — it'll print a link if so.

### Frontend — GitHub Pages

Pushing to `main` deploys automatically via
`.github/workflows/deploy-pages.yml`, as long as:

- Repo Settings → Pages → Source is set to **GitHub Actions**
- Repo Settings → Secrets and variables → Actions → Variables has
  `VITE_API_BASE_URL` set to the backend's public URL (e.g. the Tailscale
  Funnel hostname)

## Adding future migrations

```bash
cd backend
alembic revision -m "describe the change"
# Edit migrations/versions/<rev>_describe_the_change.py
# Use op.batch_alter_table() for all SQLite ALTER TABLE operations
alembic upgrade head
```

`alembic.ini` and `migrations/` are copied into the Docker image — if
either goes missing from the `Dockerfile`'s `COPY` lines, migrations will
silently no-op on every Docker deploy instead of erroring.
